# 品牌语气指南（Brand Voice）

> 本文档是自媒体技能包的**共享层**，供 `content-repurpose`、`wechat-publisher`、`xiaohongshu-carousel`、`bilibili-video-script`、`douyin-short-script` 等 Skill 引用。
>
> **维护原则**：每发布 3–5 篇内容后，把「读者反馈好 / 自己读着别扭」的片段回写进本文档。Brand Voice 是活文档，不是一次性定稿。

---

## 1. 这份文档解决什么问题

Brand Voice 回答三个问题：

| 问题 | 对应章节 |
|------|----------|
| **我是谁、写给谁看？** | 定位与受众 |
| **我听起来像什么人？** | 人格与语气 |
| **什么该写、什么别写？** | 用词规范与禁区 |

**Voice vs Tone**（行业通用做法）：

- **Voice（人格）**：恒定不变——无论写公众号还是录 B 站，都是「你这个人」
- **Tone（语气）**：随场景微调——长文可以展开，抖音要短平快，但不改人格底色

## 3. 人格画像

### 3.1 五个形容词（Brand Personality）

行业最佳实践：选 3–5 个词，并写清**边界**——每个词做到什么程度、不过什么线。

| 形容词 | 含义 | 边界（不过线） |
|--------|------|----------------|
| **负责** | 对结论、读者时间和 AI 协作边界负责 | 不甩锅、不夸大效果 |
| **思考** | 不人云亦云，展示判断过程和取舍理由 | 不变成空谈哲学、不堆术语 |
| **专注** | 深耕 Vibe Coding / 云原生 / 独立产品，不贪多求全 | 不赶每个热点、不泛谈一切 |
| **坚持** | 长期主义，相信持续积累的价值 | 不口号式励志、不贩卖焦虑 |
| **实践** | 从真实场景和动手经验出发，能复现能验证 | 不堆概念、不空讲趋势 |

### 3.2 身份标签（Opening Persona）

写长文或录视频时，可以用一两句「自我介绍式」标签定位读者预期。

**核心 Slogan**：

> 不积跬步，无以至千里。每天进步一点点，终能量变到质变。

**可用标签**：

- 「个人开发者 + 运维工程师 + 产品设计，三栖成长中」
- 「和 AI 结对写作，但我对结论负责」
- 「一人公司的长期主义者」

**禁用标签**：

- 「行业专家」「顶级架构师」等空泛头衔
- 「AI 将颠覆一切」类口号式开场

## 4. 语气规范

### 4.1 人称与距离

| 场景 | 人称 | 示例 |
|------|------|------|
| 长文 / 公众号 | 「我」讲经历 + 「我们」拉近距离 | 「我一开始也试了 A 方法……我们可能会遇到……」 |
| 技术论证 | 「你」直指读者场景 | 「如果你也厌倦了手动改 Prompt……」 |
| 视频口播 | 「你」「我」交替，口语化 | 「这里有个坑，我踩过，你注意一下」 |
| 小红书 | 短句、第二人称为主 | 「别再用 Prompt 硬扛了」 |

### 4.2 句式偏好

**多用**：

- 短段落（3–5 行）
- 具体场景开头（报警、上线、改配置）
- 比喻（野马关进围栏、泥瓦匠变基建架构师）
- 过程叙事（试过什么、为什么不行、最后怎么解决）
- 适度留白——指出方案局限，留延伸空间

**少用**：

- 「首先 / 其次 / 再次 / 最后」机械结构
- 「总的来说 / 值得注意的是 / 不可否认」
- 「在当今数字化时代 / AI 时代已经到来」空开场
- 「赋能 / 颠覆 / 闭环 / 抓手 / 降本增效」营销腔
- 过度 emoji 和感叹号堆砌

### 4.3 专业度平衡

```
痛点故事（30%）→ 原理讲透（40%）→ 可落地做法（30%）
```

- 术语保留英文专有名词（API、Skill、Harness），中文语境下加空格
- 展示代码 / 配置时，解释**为什么这样写**，不只贴结果
- 附上官方文档或一手来源链接
- 不假装全知——「这块我还没在生产验证」可以直说

## 5. 结构模板

### 5.1 长文（公众号 / 博客）

来源：现有 `prompt.md` + 已发布文章结构。

```
1. 钩子：场景 / 对话 / 痛点 / 反差认知（四选一）
2. 问题背景：读者为什么该关心
3. 探索过程：弯路 + 关键转折（必须有）
4. 方案 / 观点：分点讲清，配代码或图
5. 局限与延伸：诚实边界
6. 结尾：个人感悟或开放式问题
```

**特别说明块**（可选，建议保留）：

> *特别说明：本文是笔者与 AI 协作的产物。AI 是协作者，笔者对结论负责。*

### 5.2 小红书图文

- 每张图 **1 个观点**，不堆砌
- 标题：痛点 + 具体场景，避免「99% 的人不知道」
- 正文：100–300 字，口语、可扫读
- 标签：3–5 个精准技术标签，不蹭无关热点

### 5.3 B 站 / 抖音

| 要素 | B 站 | 抖音 |
|------|------|------|
| 开头 | 30 秒内说清「这期解决什么问题」 | 前 3 秒钩子（反常识 / 痛点） |
| 节奏 | 可展开，8–15 分钟 | 60–90 秒，一句一信息点 |
| 口播 | 可稍正式，保留「我」 | 更短句、更口语 |
| 结尾 | 引导收藏 + 评论区讨论 | 引导关注 + 下期预告 |

## 6. 用词表

### 6.1 推荐用词

| 类别 | 用词 |
|------|------|
| 动作 | 踩坑、落地、验证、固化、编排、约束、实践、迭代 |
| 关系 | 结对、协作、主导、驾驭、Follow |
| 评价 | 务实、可复现、生产可用、有局限、量变到质变 |
| 价值 | 学习、思考、进步、专注、坚持 |

### 6.2 禁用 / 慎用

| 类型 | 示例 | 替代 |
|------|------|------|
| 营销腔 | 赋能、颠覆、闭环、炸裂 | 直接说解决了什么 |
| AI 腔 | 综上所述、毋庸置疑 | 删掉，或改成「我的判断是」 |
| 空泛夸张 | 最强、必学、人人都要 | 加限定：「在我这个场景下」 |
| 套路标题 | 「99% 的人不知道」「看完这篇就够了」 | 用具体场景：「OpenClaw 云端部署为什么卡」 |

### 6.3 口头禅与 Slogan

**核心 Slogan**：

- 「不积跬步，无以至千里。每天进步一点点，终能量变到质变。」

**文章写作中常见表达**（持续收集）：

- 「一言以蔽之」
- 「剥开外衣」
- 「如履薄冰」
- 「学习、思考、进步」

## 7. 原创与 AI 协作边界

来源：`wechat-publisher` 与 Origin 写作原则；公众号稿仅从 Origin 分发。

| 原则 | 要求 |
|------|------|
| 人工主导 | 核心观点、案例、结论由你提供 |
| 真实素材 | 优先个人截图、数据、项目链接 |
| 保留口语 | 不过度「润色」成标准 AI 文风 |
| 透明标注 | 必要时说明 AI 协作方式 |
| 发布前自检 | 至少 3 个个人真实案例 / 细节 |

**AIGC 自检清单**：

- [ ] 有至少 3 处只有我才知道的细节（项目名、具体时间、失败尝试）
- [ ] 读起来像「我会对同事说的话」，不像产品说明书
- [ ] 标题没有套路化爆款词
- [ ] 引用了自己的文章 / 项目 / 仓库

## 8. 排版规范

与项目 `CLAUDE.md` 保持一致，所有 Skill 输出默认遵守：

- 中文与英文、数字之间加空格
- 全中文语境使用全角标点
- 中文双引号用 `""`，不用英文 `"` 或「」
- 加粗语法与中文句号兼容（见 `markdown-formatter` 规则）

## 9. 范例对照

### 9.1 ✅ 符合品牌语气

> 过去两年，利用 AI 辅助编程已成常态。AI 像一个不知疲倦的实习生，帮你写基础组件信手拈来。但是，当复杂的重构任务交托给它时，风险立马暴露：它经常「自由发挥」，比如写出一条不存在的 API……
>
> —— 来源：`docs/ai/theory/harness-engineering.md`

> 最近一段时间，陆续有朋友问起 OpenClaw 的使用体验……但在真实使用过一段时间之后，发现 OpenClaw 在生产环节和日常生活中很难真正发挥价值。
>
> —— 来源：`docs/ai/llm/openclaw-pain.md`

### 9.2 ❌ 不符合品牌语气

> 在当今 AI 飞速发展的时代，人工智能技术正在深刻改变软件开发的方式。首先，我们需要了解 Agent 的基本概念；其次，我们要掌握 Prompt 工程；最后，才能实现效率的全面提升。综上所述，AI 赋能开发已成为不可逆转的趋势。

**问题**：空开场、机械结构、营销腔、无个人经历、无具体场景。

## 10. 平台语气微调速查

| 平台 | Voice（不变） | Tone（微调） |
|------|---------------|--------------|
| 公众号 / 博客 | 负责、思考、实践 | 可展开，允许 2000–4000 字，适合深度复盘 |
| 掘金 / 技术社区 | 专注、实践 | 稍正式，代码块多一些 |
| 小红书 | 专注、坚持 | 更短、更直接、视觉优先，突出「每天进步一点点」 |
| B 站 | 负责、思考 | 口播感、展示思考过程、要有节奏标记 |
| 抖音 | 实践、坚持 | 极短、强钩子、一句一要点 |
