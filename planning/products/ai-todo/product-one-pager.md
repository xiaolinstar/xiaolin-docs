# AI 日省待办 · 产品一页纸

> **状态**：对内使用 · 所有对外内容的统一话术源  
> **更新**：2026-06-29  
> **小程序名**：AI 日省待办 · **英文名**：`ai-todo`

---

## 一句话

**AI 日省待办 = 给 AI Agent 用的个人待办数据层：人用微信小程序查看确认，Agent 用 CLI 写入结构化数据。**

---

## 解决什么问题

| 痛点 | 我们的做法 |
|------|------------|
| Agent 能对话，但待办没地方可靠落库 | 提供可审计的结构化 API（CLI / 未来 SDK） |
| 企业协同工具太重，个人只要提醒+日历 | 只做提醒、日历、联系人，不扩项目管理 |
| 传统 Todo App Agent 调不稳 | `--json` 输出、明确字段、联系人先查后建 |

---

## 三个核心模块

| 模块 | 回答的问题 | 典型场景 |
|------|------------|----------|
| **提醒** | 什么要在 DDL 前完成？ | 周五前报销、回家买牛奶 |
| **日历** | 什么时间点发生？ | 14:00 开会、周六 10:00 聚餐 |
| **联系人** | Agent 上下文里「谁是谁」？ | 给王总发邮件、抄送李华 |

**分类口诀**：需要打勾 `done` → 提醒；只占时间段、自然过期 → 日历。

---

## 三个明确不做

1. **不做**小程序内置 AI 聊天 / 自然语言输入  
2. **不做**重度项目管理、看板、团队协作  
3. **不做**企业 IM、文档协作、审批平台  

> AI 原生 ≠ 每个 App 里塞聊天框，而是 **可被 Agent 稳定调用、组合、审计**。

---

## 典型工作流（对外讲故事用）

```text
领导发邮件 → Agent 读邮件 → 提取行动项 → CLI 创建提醒/日历 → 用户在小程序确认处理
```

**角色分工**：

- **Agent**：理解自然语言、读外部上下文、编排动作  
- **AI 日省待办**：可靠存储、权限隔离、提醒触达  
- **小程序**：确定性查看、轻量编辑、订阅消息授权  

---

## 激活时刻（北极星相关）

用户完成 **首次激活** 的定义：

1. 打开微信小程序「AI 日省待办」并登录  
2. 创建 ≥1 条提醒或日历  
3. （7 日内）再次打开并处理至少 1 条事项  

开发者侧等价激活：创建 CLI 令牌并成功执行 `ai-todo today --json`。

---

## 目标用户（优先级）

1. **AI 工具深度用户** — Cursor、Claude Code、OpenClaw 等  
2. **自动化用户** — 脚本、工作流、邮件/工单集成  
3. **要结构化个人数据的用户** — 可导出、可审计、可自动化

## 竞品 / 替代方案定位（内部）

| 方案 | 差异 |
|------|------|
| 系统提醒 / 苹果提醒事项 | 无 Agent 接口、无结构化导出 |
| 飞书 / 钉钉待办 | 团队协作向，客户端重 |
| Todoist 等 | 面向人类操作，Agent 集成弱 |
| **AI 日省待办** | 轻量 + Agent-first + 微信触达 |
