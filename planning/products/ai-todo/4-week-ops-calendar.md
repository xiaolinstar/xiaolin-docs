## 第 1 周：立住认知，打通入口

**目标**：让人 10 秒内知道「这是什么、和谁不同、怎么找到」。

### 周一 · 产品一页纸（内部用，不对外发）

整理并固定以下话术，后续所有内容复用：

- **一句话**：AI 日省待办 = 给 AI Agent 用的个人待办数据层，人用小程序看，Agent 用 CLI 写。
- **三个模块**：提醒（DDL）、日历（时间点）、联系人（Agent 上下文）。
- **三个不做的**：不做内置 AI 聊天、不做项目管理、不做团队协作。
- **激活时刻**：打开小程序 → 创建第一条提醒 → 收到/看到提醒状态变化。

### 周二 · 站点优化

- 检查 `docs/products/ai-todo/index.md`：推荐阅读顺序是否清晰。
- 在产品 index 或 product 文末增加 **CTA 区块**：
  - 微信搜索：**AI 日省待办**
  - 开发者：`npm i -g @xiaolinstar/ai-todo-cli`
  - 深度阅读：Agent 接入（`docs/products/ai-todo/agent.md`）
- 站内相关文章（AI 实践、效率工具）至少加 **2 条内链** 到 AI 待办专栏。

### 周三 · 深度文（站点原文）

**标题建议**：《AI 日省待办：为什么我不在小程序里做 AI 对话框》

结构（2～3 小时可写完）：

1. 痛点：Agent 能说话，但待办数据没地方可靠落库
2. 方案：小程序 = 确定性 UI，CLI = Agent 接口
3. 一条典型链路：邮件 → Agent 提取 → CLI 创建提醒 → 小程序确认
4. CTA：搜索「AI 日省待办」体验

### 周四 · 公众号（轻量分发）

从周三长文拆 **800 字版**：

- 开头 3 句话讲结论
- 1 张示意图（邮件 → Agent → CLI → 小程序）
- 文末：完整架构见站点 + 小程序搜索指引

### 周五 · 种子用户触达
