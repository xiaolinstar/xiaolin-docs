# 项目通用规则

- 始终使用中文回复用户，但技术专有名词可保留英文（如 API、Python、DTO等）。
- 使用项目既有风格，不引入新风格，包括代码、文档或交互，默认延用项目中已有的格式、缩进、命名习惯。
- 尽可能少地输出内容，仅提供高信息密度回复，禁止无效寒暄、过度铺垫，只输出对当前任务有直接帮助的信息。
- 遵守[《中文文案排版指北》](https://www.bookstack.cn/read/chinese-copywriting-guidelines/README.md)标准排版格式：中文与英文之间加空格，中文与数字之间加空格；全角标点与其他字符之间不加空格。全中文语境下必须使用全角标点。
- 在安装 Skill、Subagent、Commands、MCP、Hook 时，**项目 Skill 真源一律放在 `.agents/skills/`**（Agent Skills 标准目录，Codex / Antigravity / OpenCode 原生读取）。若目标工具只认 `.claude/skills/`（Claude Code、Cursor），在 `.claude/skills/<name>` 创建符号链接指向 `.agents/skills/<name>`，禁止维护双份真源。必须同步在项目根目录的 `skills-lock.json` 中登记（含 `source`、`sourceType` 等字段），防止依赖记录丢失。
- 文档命名规范：必须全部使用小写字母，文档名需与文章内容主题紧密契合，多个单词间使用 `-` 分隔。命名应精简，不超过 4 个词汇（单词），以 3 个词以内为宜。
- Markdown 语法与渲染兼容性检查：中文全角标点（特别是中文句号 `。`）可能阻断加粗标记（`**`）的解析导致渲染失败。必须在加粗语法的外部添加半角空格隔离（如 `文本 **加粗** 文本`），或者将标点符号包含在加粗语法内部（如 `**加粗句子。**`）来确保完全兼容。撰写文档后，应习惯性通过类似 `markdown-formatter` 技能修正此问题。
- 术语与知识库规范：领域术语以 `docs/glossary/` 为唯一释义真源。正文优先使用短码 `{{term:规范名或id}}`；构建期会对知识库词（含 aliases）做自动匹配。同一篇文章内，每个术语仅在**首次出现**时挂悬停释义并插入旁注，后续出现保持纯文本，避免重复提示。禁止再用直角引号「」作为术语机器锚点（避免与旧约定混淆）。一般引用、口语转述使用弯引号“”；嵌套用『』。新增术语须先入库（`id`/`term`/`definition`，可选 `aliases`）再在正文使用。禁止在 Markdown 链接文案或图片 alt 内使用 `{{term:…}}`（会破坏语义 / 交互）。
- 引号与加粗结合规范：弯引号与加粗并存时，加粗在引号内：`“**强调**”`。
