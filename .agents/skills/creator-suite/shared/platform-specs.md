## 1. 内容层级与分发策略

### 1.1 一源多用架构

```
                    ┌─────────────────────┐
                    │  VitePress 站点      │  ← 权威原文、SEO、长期沉淀
                    │  xiaolinstar.cn     │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
        公众号 / 掘金      小红书图文         B 站 / 抖音
        （深度 / 搜索）    （要点 / 视觉）    （演示 / 口播）
```

| 层级 | 载体 | 职责 |
|------|------|------|
| **L0 原文** | VitePress 站点 | 完整方案、配置、内链、可复用清单 |
| **L1 长文分发** | 公众号、掘金、知乎 | 结论 + 要点 + 引导回站点 |
| **L2 视觉分发** | 小红书 | 单观点信息图 + 短文案 |
| **L3 视频分发** | B 站、抖音 | 演示、口播、实操录屏 |

### 1.2 分发原则

- **站点发完整版**，平台发「钩子 + 要点」，文末 / 简介引导回站点拿配置与清单
- **同一主题**各平台角度不同，避免全文复制粘贴
- **发布顺序建议**：站点定稿 → 公众号 / 掘金 → 小红书组图 → 视频（可选）

### 1.2.1 Origin 与 Output（定稿）

| 问题 | 结论 |
|------|------|
| **原文放哪？** | `docs/` — 唯一权威 Origin，VitePress 公开收录 |
| **加工文放哪？** | `content/dist/{slug}/` — 与 Origin 分离，**不上站** |
| **是否提交 Git？** | Origin ✅；Output 文本 ✅；Output 视频 mp4 ❌（仅脚本入库） |
| **是否在站点展示？** | Origin ✅；Output ❌（避免重复内容伤 SEO、混淆读者） |

```
Origin（docs/）          Output（content/dist/）
     │                           │
     │  content-repurpose        │
     └──────────────────────────►├── meta.yaml（溯源 + 发布状态）
                                 ├── wechat.md
                                 ├── xiaohongshu.md
                                 └── …
```

**与 Origin 完全一致的同步**（如掘金全文）：在 `meta.yaml` 记录 `sync: origin`，不重复存 md。

**历史路径**：`docs/sre/devops/wechat/` 已于 2026-06-25 迁移至 `content/dist/`；VitePress `srcExclude: ['**/wechat/**']` 防止误收录。

详见 [content/dist/README.md](../../../content/dist/README.md)。

## 3. 各平台规格速查

### 3.1 VitePress 站点（权威原文）

| 项目 | 规格 |
|------|------|
| **定位** | 完整方案、系列专栏、可复用资产 |
| **字数** | 深度文 2000–5000 字；轻量文 800–1500 字 |
| **Frontmatter** | 遵循项目规范：`title`、`description`、`date`、`category`、`tags` |
| **结构** | 结论先行 → 最小可行方案 → 原理与权衡 → 落地材料 → 关联阅读（≥3 条内链） |
| **SEO** | 1 个主关键词 + 3 个长尾词；`description` 120 字内 |
| **配图** | 封面 + 信息图；CDN `https://media.xiaolin.fun/docs/img-{slug}/` |
| **索引** | 新增文档同步更新 `docs/.vitepress/config.mts` |

**轻量文 vs 深度文**：

| 类型 | 字数 | 产出时间 | 用途 |
|------|------|----------|------|
| 深度文 | 2000–5000 | 4–8 h | 系列核心、SEO 主力 |
| 轻量文 | 800–1500 | ≤2 h | 单点结论、多平台分发源 |

### 3.2 微信公众号

| 项目 | 规格 |
|------|------|
| **定位** | 流量入口、读者关系、深度复盘 |
| **字数** | 1500–4000 字（与 Brand Voice 一致） |
| **标题** | ≤64 字；优先问题型 / 经验型，见 brand-voice §6.2 |
| **摘要** | 80–120 字，第一人称，突出个人体验 |
| **封面图** | 比例 **2.35:1**（推荐 900×383 px）；**中心安全构图**（后台会裁切边缘） |
| **正文配图** | 宽度约 1080 px；优先个人截图、原创信息图 |
| **段落** | 每段 3–5 行；适当引用块、列表 |
| **结尾** | 互动提问 + 站点链接 + 可选二维码 |
| **发布时段** | 工作日 12:00–13:00 或 20:00–22:00（可 A/B 测试） |

**封面图设计要求**（来自 `wechat-publisher`）：

- 包含主题元素或吸睛标题
- 构图居中，兼容横向裁剪
- 优先原创，非模板化

**发布 checklist**：

- [ ] 摘要 80–120 字，第一人称
- [ ] 封面 2.35:1，中心安全区
- [ ] ≥3 处个人真实细节
- [ ] 引导回站点原文
- [ ] 后台预览排版正常

### 3.5 小红书

| 项目 | 规格 |
|------|------|
| **定位** | 视觉种草、单观点传播、年轻工程师触达 |
| **图片数量** | 3–12 张（见 `notion-infographic-v2` 规则） |
| **图片比例** | 推荐 **3:4**（1080×1440）；封面尤其重要 |
| **单图原则** | 每张图 **1 个核心观点**，不堆砌 |
| **标题** | ≤20 字可见区；痛点 + 具体场景 |
| **正文** | 100–300 字为佳；上限 1000 字；口语、可扫读 |
| **话题标签** | 3–5 个 `#话题`；精准技术向，不蹭无关热点 |
| **tone** | 专注、坚持；可呼应 Slogan「每天进步一点点」 |

**组图结构**（与 `notion-infographic-v2` 对齐）：

```
第 1 张：封面（主题 + 核心价值）
第 2–N-1 张：内容图（每图 1 观点）
第 N 张：总结 / 行动号召（可选）
```

**视觉风格**（使用 `notion-infographic-v2` 时）：

- Notion 手绘线稿风；主色纯黄 + 黑色压实
- Skill 默认输出 16:9 → 发布前需裁切或调整为 **3:4**，或生图时指定比例

**标题公式**：

| 类型 | 示例 |
|------|------|
| 痛点型 | Cursor Skills 配置了还是乱改代码 |
| 反差型 | 别再硬写 Prompt 了 |
| 清单型 | AI 运维必做的 3 件事 |
| 进度型 | 独立产品第 30 天复盘 |

**发布 checklist**：

- [ ] 封面 3:4，前 1 秒能看懂主题
- [ ] 每张图只 1 个观点
- [ ] 正文 ≤300 字
- [ ] 3–5 个精准 `#话题`
- [ ] 评论区预埋 1 个引导问题

### 3.6 哔哩哔哩（B 站）

| 项目 | 规格 |
|------|------|
| **定位** | 深度教程、实操演示、系列沉淀 |
| **时长** | **8–15 分钟**（教程类）；最短不低于 3 分钟 |
| **封面** | **1146×717** 或 **1920×1080**（16:9）；大字 + 高对比 |
| **标题** | ≤80 字；说清「这期解决什么问题」 |
| **简介** | 200–500 字；时间戳章节 + 链接 + 标签 |
| **标签** | 5–10 个；含 1–2 大标签 + 若干精准长尾 |
| **分区** | 科技区 → 软件应用 / 计算机技术（按内容选） |
| **开头** | **30 秒内**说清价值，避免冗长自我介绍 |
| **tone** | 负责、思考；展示思考过程，保留「我」 |

**视频结构模板**：

```
00:00  钩子（痛点 / 反常识）
00:30  这期要解决什么 + 适合谁
01:00  背景 / 踩坑经历
03:00  核心讲解 / 实操演示
08:00  总结 + 局限
结尾   引导收藏 + 评论区互动 + 站点链接
```

**≥5 分钟视频**：建议添加**章节时间戳**（便于跳转与 SEO）。

**简介模板**：

```markdown
【本期要点】
1. …
2. …
3. …

【适用人群】AI Follower / 运维工程师 / …

【相关链接】
站点原文：https://xiaolinstar.cn/...
GitHub：...

#VibeCoding #Cursor #云原生
```

**账号**：矩阵主号 **AI持续运维**（新建；「街巷行动科」美食号停更或 archive）。

### 3.7 抖音

| 项目 | 规格 |
|------|------|
| **定位** | 短平快、强钩子、单点传播 |
| **时长** | **60–90 秒**（知识类）；上限 3 分钟 |
| **比例** | **9:16** 竖屏（1080×1920） |
| **标题** | ≤30 字 |
| **文案** | 50–150 字；补充口播未说完的信息 |
| **话题** | 3–5 个 `#话题` + 可选挑战标签 |
| **开头** | **前 3 秒**必须出钩子（反常识 / 痛点 / 数字） |
| **字幕** | 必须；短句、关键词高亮 |
| **tone** | 实践、坚持；一句一信息点 |

**60 秒脚本结构**：

```
0–3s   钩子：「Cursor 改代码越改越乱？不是模型的问题。」
3–10s  痛点共鸣
10–45s 3 个要点（每点 ~10s）
45–55s 一句话总结
55–60s 关注 + 下期预告
```

**与 B 站关系**：同一主题，B 站讲透，抖音讲「一个结论」；不要直接裁 B 站长视频。

**账号**：矩阵副号 **一只羊驼驼**（与小红书同矩阵，引流主号 AI持续运维）。

## 6. 标签体系

### 6.1 支柱 → 核心标签

| 支柱 | 中文标签 | 英文 / 混合标签 |
|------|----------|-----------------|
| Vibe Coding | Vibe Coding、AI 编程、Cursor | Agent、Skills、Harness |
| 云原生 | 云原生、DevOps、SRE | Kubernetes、CI/CD |
| 独立产品 | 独立开发、一人公司、独立创作 | 产品设计、Indie Hacker |

### 6.2 跨平台标签策略

| 平台 | 策略 |
|------|------|
| 掘金 | 技术精准标签，利于搜索 |
| 小红书 | 1 个大标签 + 2–3 个精准标签 + 1 个场景标签 |
| B 站 | 5–10 个，含分区相关词 |
| 抖音 | 3–5 个，可含流量标签但不超过 2 个泛标签 |

### 6.3 禁用标签行为

- 不蹭与内容无关的顶流话题
- 不堆砌超过 10 个标签
- 不使用误导性标签（内容与标签不符）
