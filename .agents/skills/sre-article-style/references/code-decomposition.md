# 技术文章代码拆解方案集合

代码需要读者理解，也可能需要复制运行。先明确用途，再选择讲解结构。不要机械按行数切块；拆开后仍需保留上下文、数据流与执行边界。

| 方案 | 适用内容 | 展示方式与限制 |
| --- | --- | --- |
| 整体骨架 → 逐层展开 | 嵌套配置、语法包含关系 | 先给最小整体，再展开子结构；片段有重复上下文时明确不可拼接 |
| 整体流程 → 分阶段说明 | 有明确顺序的操作 | 先说明输入、输出和阶段，再解释动作；保持先后与失败处理含义 |
| 调用入口 → 关键实现 | 跨函数、文件或脚本调用 | 标明文件名、接口、配置与执行位置，不把未提供的脚本当作现成实现 |
| 最小示例 → 逐步增加能力 | 入门与能力演进 | 明确每一步修改内容及最终版本，避免读者混用不同版本 |
| 关键片段 → 完整代码入口 | 全文完整展示妨碍阅读 | 标明节选、遗漏内容与完整来源，不把片段称为完整可运行程序 |
| 保持语义的源码分行 | 过长参数或单条命令 | 仅在语法允许处换行；核查引号、变量展开、续行与运算符语义 |

## 作者评审与候选渲染

- 使用流程：发现超限或阅读困难 → 确认用途（理解逻辑、复制片段、完整运行）→ 选择适用方案 → 生成可渲染候选 → 作者或开发者评审 → 决定修改 Origin、分发稿或 SLA → 验证。
- 原文与分发适配分开决策。只有作者授权后才同步修改 Origin；已获授权的修改直接执行，不重复请求确认。
- 每种渲染格式的 SLA 由目标平台规范维护；公众号以 wechat-publisher 的格式集合为准，不将公众号行宽上限当作所有站点代码的通用语法限制。
- 长代码块和单条长命令独立检查。块变短不代表行宽可读；长命令必须向作者展示实际效果、取舍与语义风险，由作者选择，不自动强制续行或抽取函数。
- 可渲染候选使用实际文章上下文和目标平台样式，支持复制到编辑器评审；记录方案、文件、适用范围与验收结果。未经确认不自动覆盖已通过版本。
- 骨架、局部片段、伪代码和完整文件必须明确区分；声明片段是否可独立运行、能否顺序拼接、如何组成完整实现。省略必须明示，不静默删除必要逻辑。
- 保留执行环境、输入输出、凭据作用域与失败处理。改写后做与变化相称的验证；结构、词法检查不能代替编译、运行或平台验收，不执行部署来验证排版。

文章正文只解释有助于理解技术的结构和取舍，不混入渲染实现细节或内部 SLA 术语。具体文章示例及作者决策放在文章或分发目录，通用方案只在此维护。
