## 需求描述

注册微信小程序账号，并开发上架一个线下发牌器小程序（定名为“我的聚会助手”），包含完整的功能开发、审核上架流程，为未来扩展到其他桌游做准备。

### 背景与动机

随着线下聚会活动的增多，各类聚会桌游越来越受欢迎，但传统的发牌方式效率低下且容易出错。开发一个线下发牌器小程序可以提升游戏体验。由于微信存在严格的分类审核机制，不允许出现涉嫌游戏的敏感词汇（如“谁是卧底”、“阿瓦隆”等），加之原名“吉米”可能涉及商标侵权风险，因此采用纯工具化、中性且规避风险的名称“我的聚会助手”进行上架和运营。

### 核心需求

1. **微信小程序注册**：完成微信小程序账号注册和认证
2. **内容合规机制**：全面规避可能引发违规、涉嫌游戏或商标侵权的设计元素及文案
3. **小程序信息配置**：准备并填写合规的小程序名称、简称、简介、头像等信息
4. **核心发牌功能**：实现随机发牌、角色分配、游戏规则等核心功能
5. **小程序审核上架**：提交审核并确保通过后成功上架
6. **扩展兼容性**：设计架构支持未来添加其他桌游玩法，并同步确保符合工具助手分类的合规要求

### 非功能性需求

1. **易用性**：界面简洁直观，操作流程清晰
2. **可扩展性**：模块化设计，便于添加新游戏
3. **兼容性**：支持主流微信版本和设备
4. **可维护性**：代码结构清晰，文档完善

### 经验教训

1. **前置资质流程**：不要等代码写完了再去申请发布。应尽早先行启动小程序的注册、基本信息填写及备案审查周期；待上述流程妥当之后，再执行最终的代码审核提交，能大幅压缩等待时间。
2. **合理选择工具类目**：此类服务工具在提交申请时，应当优选放入「工具类」类目之下，这属于审核门槛最低且最容易自证的合规范畴。
3. **杜绝越级涉猎游戏属性**：在任何文案、简介、名称层面，都要极其严肃地规避“游戏”、“联机”、“对抗”等敏锐词汇；一旦触及这类定性词，会被直接按小游戏标准强制要求多项资质，致使过审无望。

### 审核与上线踩坑记录

由于微信对工具类目与游戏类目有非常严苛的界限判定，本次上架我们彻底放弃了游戏相关命名并改为纯工具性质。

**核心踩坑记录汇总：**

1. **上架顺序倒置风险**：开发初期的陷阱是“先干代码然后走流程”。实操验证，必须先走「账号注册 -> 完善基础信息 -> 工信部备案」的前置基建途径，因为备案需要相对较长的政府和平台审核等待时间。只有在这部分完成出证后，最后阶段再去进行代码包上传过审才是最顺滑的模式。
2. **名称与类目定性风险**：任何诸如“桌游”、“游戏平台”、“联机”的文案都会触发系统警报拦截。由于平台对于多数服务倾向于归纳至工具类型，为了证实在业务逻辑上这是一个“工具”，其主营申请类目必须坚决圈定在「工具」中，整个门面描述中切勿出现任何线上互动特质导向，如果越线被判定成了小游戏模块，将会直接面临卡审。
