AI 待办是一个轻量级的 AI 原生待办系统，以微信小程序为核心入口，核心模块包括提醒、日历与联系人，并通过 Skill、CLI 与 OpenClaw、Claude Code 等 AI 工具集成。其微信小程序官方名称为「AI 日省待办」，英文名为 `ai-todo`。

它不尝试在应用内部做自然语言解析，也不把 AI 助手或 AI 对话框集成到小程序中，而是先提供稳定、结构化、可审计的 CLI，让 AI Agent 把自然语言转换成确定的数据操作。

## 产品理念

AI 待办的设计理念围绕三个维度展开：面向 Human 与 Agent 的双重设计、轻量级设计、开放与多平台支持。

### 面向 Human 与 Agent

AI 待办同时服务于人类用户和 AI Agent：

- **面向人类**：提供微信小程序图形化界面，无需安装 App，直接嵌入微信生态，支持快速记录、查看和管理待办事项。
- **面向 Agent**：当前优先提供结构化 CLI，支持 `--json` 输出，方便 OpenClaw、Claude Code、Cursor 等 AI 工具稳定调用。

人类偏爱视觉化和确定性交互，Agent 更适合处理自然语言和结构化数据转换。AI 待办的职责不是替代 Agent，而是成为 Agent 可调用的个人事务数据层。

典型工作流：

```text
领导发送邮件 -> Agent 读取邮件 -> 提取行动项 -> 创建提醒或日程 -> 用户在小程序确认和处理
```

在这个模式下，Claude Code 这类 AI Workspace 更像个人办公系统的数据总线：邮件、文档、即时通信、待办、日历都可以变成 Agent 上下文的一部分，再由 AI 待办负责可靠存储和提醒。

### 轻量级设计

AI 待办的轻量化体现在功能边界上。

飞书、钉钉、企业微信等企业级协同工具功能完整，但它们的任务系统通常面向团队协作和项目管理。对个人轻办公用户来说，仅仅为了管理日历和提醒，就要长期依赖一个较重的客户端，并不划算。

在 AI 待办中，「待办」是整个系统的上位概念，不等同于某一个具体模块。它主要由三类轻量能力组成：

- 提醒事项：有截止时间，但不占用固定日历时间块；
- 日历：在明确时间点或时间段发生的事项；
- 联系人：为 Agent 提供可检索的人员上下文。

### 开放与多平台支持

AI 待办的开放性主要体现在两个层面：

- **面向任意 AI Agent 开放**：只要 Agent 能调用 CLI，就可以接入 AI 待办（CLI 命令名称仍为 `ai-todo`）。
- **面向外部系统集成预留空间**：当前先支持 CLI，未来可以继续提供 Python SDK，让 AI 待办集成到更多自动化脚本、个人工作流和业务系统中。
- **基于微信生态覆盖多端**：小程序天然覆盖手机端和电脑端（微信对各类操作系统和芯片架构的支持），提醒可通过微信订阅消息触达用户。

因此，它不依赖特定操作系统，也不要求传统 App 常驻后台。

## AI 待办不做什么

如果只看微信小程序界面，AI 待办很容易被误解成一个普通提醒工具。这是刻意设计的结果。

AI 待办不把 AI 助手、AI 对话框或自然语言输入框集成到小程序里，未来也不计划这样做。原因是：AI 原生不等于在每个应用里塞一个聊天框，而是让应用具备被 AI Agent 稳定调用、组合和审计的能力。

在这个设计里，小程序负责确定性的查看、确认和轻量编辑；AI Agent 负责理解自然语言、读取上下文、编排外部系统；AI 待办负责保存结构化数据，并提供可靠接口。

因此，AI 待办明确不做这些事情：

- 不做内置 AI 聊天助手；
- 不在小程序中做自然语言解析；
- 不做重度项目管理；
- 不做复杂团队协作流；
- 不做企业 IM、文档协作和审批平台；
- 不把任务模块扩展成团队管理系统。

这种克制是产品边界，也是 AI 原生设计的一部分。

## 核心模块

### 提醒事项

提醒事项是一段时间内完成即可、偏向 DDL 的事项。它回答的是：「有什么事情需要我记得在某个截止日期前完成？」

典型场景：

- 周五前提交报销；
- 晚上记得给家人打电话；
- 回家前去超市买牛奶。

提醒事项关注事情本身和完成状态，通常有截止日期，但不占用日历上的固定时间块。

### 日历

日历是与时间强相关的事项，且往往不需要事先准备，在功能实现上与闹钟更贴近。它回答的是：「我在某个特定时间需要做什么？」

典型场景：

- 今天 14:00 科室内开会；
- 周六 10:00 和朋友张三去参观南京博物院；
- 明天 19:00 聚餐。

日历关注明确时间点或时间段，可记录会议室、链接、地点和备注。

### 联系人

联系人是 AI 个人助理的基础上下文能力。

Agent 在处理任务时，可以通过姓名、全拼、昵称等信息检索联系人，再自动关联邮箱、电话、公司等字段。

典型场景：

- 把会议纪要发给部门同事，并抄送部门领导；
- 下周有个项目，需要联系明华开会；
- 给客户王总发送报价确认邮件。

联系人让 Agent 稳定知道「某个人是谁，以及可以如何联系」。

## 适用人群

AI 待办适合三类用户：

- **AI 工具深度用户**：已经在使用 OpenClaw、Claude Code、Cursor 等工具，希望让 AI 管理个人事务。
- **自动化与系统集成用户**：当前可以通过 CLI，把提醒、日历和联系人接入自己的脚本或工作流；未来也可能通过 Python SDK 集成到业务系统。
- **需要结构化个人数据的用户**：希望待办、日程和联系人数据可导出、可审计、可自动化。

## 总结

AI 待办不是另一个传统提醒应用，而是一个 AI 原生的个人事务数据平台。

它把「理解自然语言」交给 AI 工具，自己专注做好「可靠存储、确定操作与结构化接口」。
