## 推荐方案（详）

### 方案 1（最小调整）—— 推荐起步

**动作**：仅修正高级/加餐 10 处 title 编号错位（类似中级篇此前做法）

**优点**：
- 改动最小、风险最低
- 不涉及文章归属变动，保留现状学习路径

**缺点**：
- 未解决主题边界模糊问题（高级篇三主题混合）

**commit 信息建议**：
```
fix(devops): 修正高级/加餐篇 10 篇 frontmatter title 编号偏移（−3）
```

### 方案 2（主题梳理）—— 推荐主推

**动作**：方案 1 + 父标签重命名

- 高级篇父标签：`DevOps 高级篇` → `DevOps 高级篇：质量门禁与变更管控`
- 加餐篇父标签：`DevOps 加餐篇` → `DevOps 加餐篇：典型案例与横向能力`

**优点**：
- 父标签文案承担"主题提示"职责，弥补单级内多主题混合的问题
- 文章归属不变，风险可控

**缺点**：
- 仍未解决 13 与 26 的归属问题

**commit 信息建议**：
```
refactor(devops): 重命名高级/加餐篇父标签，明确主题边界
```

### 方案 3（结构调整）—— 改动最大

**动作**：方案 2 + 文章归属调整

- 中级篇 13 私有镜像仓库治理 → 高级篇（与 19 SBOM 同主题）
- 加餐篇 26 多模块 Git 协作 → 基础篇附录（作为 04 Git 篇的延伸）
- 同步更新 sidebar 顺序与编号

**优点**：
- 主题边界最清晰
- 13 移到高级后，"制品治理"小节自然形成
- 26 移回基础后，Git 主题连贯

**缺点**：
- 跨级文件移动，需要同步更新 sidebar / index.md 表格
- 调整后中级篇只剩 7 篇 + 00 导读；高级篇变 7 篇；加餐篇变 3 篇；基础篇增加附录

**commit 信息建议**：
```
refactor(devops): 13 移入高级篇（制品治理主题合并）、26 移回基础篇（Git 主题连贯）
```
