已有 [Linux 起手式](./linux-guide.md) 介绍了 zsh、oh-my-zsh、Git、Docker 等云服务器常用工具。本文在此基础上继续梳理云服务器初始化动作，让它更适合作为 DevOps 基础读者的长期入口。

## 文章定位

这篇文章不是从零重复讲 Linux 命令，而是整理云服务器初始化的标准动作，让新服务器从「刚买完」进入「可以长期维护」状态。

## 读者问题

1. 新买一台 Ubuntu 云服务器后，第一小时应该做什么？
2. 为什么推荐普通用户 + `sudo`，而不是长期使用 `root`？
3. 哪些工具属于必装，哪些可以后置？
4. 配好一次服务器后，如何通过镜像或快照复用？

## 内容大纲

### 操作系统选择

推荐 Ubuntu LTS，解释 LTS、版本选择、预装面板与纯净系统的取舍。

### 默认用户与权限

统一使用 `ubuntu` 普通用户，日常操作通过 `sudo` 提权，减少误操作风险。

### 基础软件

最小安装清单：

- `git`
- `curl`
- `wget`
- `zsh`
- `tree`
- `htop`
- `unzip`

### zsh 与插件

从「好看」调整为「提高命令行反馈质量」：自动补全、语法高亮、历史建议、Git 状态提示。

### SSH 与密钥

承接 DevOps 基础篇，说明从密码登录过渡到 SSH 密钥登录的路径。

### 镜像与快照

完成初始化后制作云服务器镜像或快照，减少重复配置。

## 交付标准

读者完成本文后，应能：

1. 初始化一台可长期维护的 Ubuntu 云服务器。
2. 使用普通用户完成日常运维操作。
3. 配置基础 shell 增强能力。
4. 保存可复用的服务器初始化成果。
