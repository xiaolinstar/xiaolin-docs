上一篇文章，我们在本地用 Nginx 跑通了静态资源代理。但 `http://localhost` 只有你自己能看到——别人访问不了，电脑关机就断了。

这篇文章要解决的问题是：**如何让网站真正「上线」？**

## 什么是生产环境

开发环境和生产环境的本质区别，不在于用了什么技术，而在于**谁在用、什么时候能用**。

| | 开发环境 | 生产环境 |
| --- | --- | --- |
| 用户 | 你自己 | 任何人 |
| 可用时间 | 用的时候开着 | 7×24 小时 |
| 网络 | localhost / 内网 | 公网可访问 |
| 数据丢了 | 重来就行 | 是事故 |

生产环境有两个**最低必要条件**：

1. **7×24 小时运行**——你的笔记本合盖就断，不满足
2. **具备公网 IP**——局域网里的服务外面访问不到，不满足

缺一个都不算「上线」。这两个条件解决的是「**能访问**」——至于安全、备份、监控，那是后续文章的事。

## 为什么选择云服务器

满足 7×24 + 公网 IP 这两个条件，有几种方式：

| 方式 | 7×24 | 公网 IP | 成本 | 适合场景 |
| --- | --- | --- | --- | --- |
| 自建物理机 | 需自备机房和 UPS | 需申请固定 IP | 高 | 大型企业 |
| 虚拟主机 | ✅ | ✅ | 低 | 静态网站，功能受限 |
| 云服务器 | ✅ | ✅ | 按需付费 | 绝大多数场景 |

云服务器是大多数人触达「两个必要条件」的**最短路径**。花几十块钱租一台，几分钟就能拿到一个公网可访问的服务器。

主流云厂商都提供轻量应用服务器，个人项目完全够用：

- [腾讯云轻量应用服务器](https://cloud.tencent.com/product/lighthouse)
- [阿里云轻量应用服务器](https://www.aliyun.com/product/swas)
- [华为云轻量应用服务器](https://www.huaweicloud.com/product/ecs.html)

> 选购建议：入门选最低配即可（1 核 2G），操作系统选 Ubuntu 22.04 或 24.04。

## 准备工作

### SSH 连接服务器

云服务器购买完成后，拿到公网 IP 地址，通过 SSH 连接：

```bash
ssh root@你的公网IP
```

首次连接会提示确认指纹，输入 `yes`，然后输入密码即可登录。

连接成功后，你会看到类似这样的终端提示：

```text
Welcome to Ubuntu 24.04 LTS (GNU/Linux 5.15.0-xx-generic x86_64)

root@your-server:~#
```

这说明你已经登录到一台运行在云端的 Linux 服务器上了。

### 安装 Nginx

在服务器上安装 Nginx（和本地一样的步骤）：

```bash
sudo apt update
sudo apt install nginx
```

验证安装：

```bash
nginx -v
```

启动 Nginx：

```bash
sudo systemctl start nginx
sudo systemctl enable nginx
```

> `systemctl enable` 让 Nginx 开机自启，确保 7×24 可用。

此时在浏览器访问 `http://你的公网IP`，应该能看到 Nginx 默认欢迎页面。恭喜，你的服务器已经在公网可访问了。

## 第一次手动部署

现在把本地的网站文件传到服务器上。

### 本地构建

在本地项目目录中构建生产版本：

```bash
pnpm run docs:build
```

构建产物在 `docs/.vitepress/dist/` 目录下。

### 上传到服务器

使用 `scp` 命令将构建产物上传到服务器：

```bash
scp -r docs/.vitepress/dist/* root@你的公网IP:/var/www/html/
```

这条命令做了什么：

- `scp`：基于 SSH 的文件复制命令
- `-r`：递归复制目录
- `dist/*`：构建产物的所有文件
- `root@你的公网IP:/var/www/html/`：复制到服务器的 Nginx 静态资源目录

上传完成后，在浏览器访问 `http://你的公网IP`，看到你的网站了——这就是「上线」。

## 域名（可选）

直接用 IP 访问没问题，但 `http://42.192.77.66` 不如 `http://my-blog.com` 好记。

域名需要单独购买（在域名注册商如腾讯云 DNSPod、阿里云万网），然后做 DNS 解析，将域名指向你的服务器 IP。

添加一条 A 记录：

| 记录类型 | 主机记录 | 记录值 |
| --- | --- | --- |
| A | @ | 42.192.77.66 |

解析生效后（通常几分钟），就可以通过域名访问了。

如果需要 HTTPS（浏览器地址栏显示小锁），还需要申请 SSL 证书，这属于安全话题，后续文章会讲。

## 手动部署的痛点

到这里，你已经完成了一次完整的「本地 → 服务器」部署。流程是通的，但有几个明显的问题：

**每次改代码都要手动 scp**

改一行文字，也要走一遍 `build → scp → 验证` 的流程。

**没有版本记录**

`scp` 是直接覆盖文件，覆盖了就没了。如果新版本出了问题，想回滚到上一个版本？没有。

**多人协作怎么办**

两个人同时 `scp` 到同一台服务器，谁覆盖谁？

这些问题指向同一个答案：**需要版本管理工具**。

## 小结

生产环境的两个最低必要条件是 7×24 和公网 IP，云服务器是最短路径。通过 SSH 连接服务器 + scp 上传文件，就能完成一次最朴素的手动部署。

手动部署能跑通，但不高效、不安全、不可追溯。下一步，我们引入 Git 和 GitHub，用版本管理来解决这些问题。
