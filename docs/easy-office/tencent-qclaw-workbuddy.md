# 完全面向 AI 工具办公，替代豆包

近些时间，我对 AI 工具的使用越来越多，Claude Code、Codex、Cursor、OpenClaw、TRAE、CodeBuddy 等，越来越觉得大模型作为通用人工智能，不止在 Coding 领域可以大展身手，在办公场景中也可以发挥重要作用。

因此，我最近在思考和实践**完全使用 AI 工具**来处理日常办公任务。

聚焦到办公领域，腾讯推出两款产品——QClaw 和 WorkBuddy，引发了不少关注。作为一个长期关注 AI Agent 发展的技术爱好者，我下载了 2 款产品并体验产品经理的设计理念。不止是腾讯，其他公司也均推出了类似的产品：

- Kimi：Kimi Claw，支持云端服务器、本机和安卓手机。
- Xiaomi：MiMo Claw
- Alibaba：QoderWork

智能体（Intelligent Agent），也常被称为"AI Agent"，是指一种能够自主感知环境、做出决策并采取行动以实现特定目标的系统。从我的视角来看，AI Agent 分为两种类型：

- OpenClaw：根植于操作系统的服务进程，支持通过自然语言指令让 AI 自动操作电脑完成各种任务。
- Claude Code：最初为 AI Coding 设计的应用软件，支持在终端里与 AI 交互完成任务。

目前，上述 2 类产品均支持 Agent Skills，这种扩展能力使得其延伸为通用 AI Agent，用户可以根据自己的需求自定义任务场景和技能。

从产品体验来看，腾讯推出的两款产品，分别为 OpenClaw 系列 和 Claude Code 系列衍生产品：

- **QClaw**：定位为零门槛的个人用户市场，主打一键安装和微信直连
- **WorkBuddy**：定位为职场办公场景，主打企业级功能和多 Agent 协作

这两款产品都是面向最广大普通轻度办公人群，缺乏计算机基础能力，无法直接驾驭 OpenClaw 和 Claude Code 这类产品。简单来说，是面向用户的友好性封装。

## 用户友好，专家团

在使用方式上，腾讯的两款产品都提供了友好的用户界面。QClaw 和 WorkBuddy 都将“专家”作为用户使用的入口，用户需要先安装“专家”，然后调用其为我们工作。

WorkBuddy 专家中心：

专家是包含了特定任务场景领域知识和技能的扩展包，用户可以根据自己的场景选择不同的专家。应用官方在专家广场发布了大量的专家，用户都可以开箱即用。

从产品形态上讲，这两款产品都旨在将 AI Agent 扩展到更广大的办公场景中，降低通用智能体的使用门槛。之前都是计算机专业领域的用户在使用，现在可以面向更广大普通用户。直白的说，这类产品的目标就是要替代传统的对话式 AI 应用，如豆包、千问、元宝等。

以技术的视角看，我认为这类产品定位存在问题或矛盾：

- 轻度办公人群：上手起来仍有难度，只能使用简单的开箱即用的功能，难以满足较复杂的需自定义的任务场景。
- 专业用户：没有带来新的技术价值，增加了不必要的封装，灵活性差，且不支持外接模型。

综上所述，如果你之前主要是豆包的用户，那么建议你尝试这两款产品。

如果你是相对专业用户，我觉得可以参考和借鉴产品设计，但真用起来还是不够灵活，对自定义任务场景的支持有限。另外，这两款产品都不支持外接模型，不符合当前 Agent 和 LLM 分离的发展趋势，可迁移性也不够好。
