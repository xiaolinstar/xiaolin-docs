
# ai-todo：AI 原生的待办、日历与联系人管理系统

ai-todo 是一个轻量级的 AI 原生待办管理系统，以微信小程序为核心入口，不内置自然语言解析能力，支持多端多平台，通过自动闭环 SKILL 与 OpenClaw、Claude Code 等 AI 工具无缝集成，当前优先提供稳定、结构化、可审计的 CLI。

## 产品理念

ai-todo 的设计理念围绕三个核心维度展开：

### 面向 Human 与 Agent 的双重设计

ai-todo 同时服务于人类用户和 AI Agent，提供不同的交互入口：

- **面向人类**：提供直观的微信小程序图形化界面，无需安装 App，直接嵌入微信生态，电脑端也可登入使用；支持快速记录、查看和管理待办事项，操作规则清晰确定，符合人类使用习惯
- **面向 Agent**：当前优先提供结构化的 CLI，支持 `--json` 输出，方便 OpenClaw、Claude Code、Cursor 等 AI 工具稳定调用

人类在信息处理上偏爱视觉图形信息，而 Agent 更擅长处理自然语言，其强大的推理理解能力可将自然语言解析为结构化数据，且应用到以结构化数据为中心的软件系统中。

最佳的使用场景：

用户在办公时，完全以自然语言的方式，让 AI Agent 帮助管理待办、日程和联系人，甚至用户可以接入在线文档、邮箱、即时通信等，由 Claude Code 驱动的 Agent 来自动处理办公数据。

领导发送邮件 -> Agent 读取邮件 -> 提取信息，创建待办或日程

所有的工作倾向于使用 Claude Code 构建的 AI WorkSpace，其好像是计算机系统中的数据总线，将各类应用作为节点，节点间进行信息交互，系统数据纳入到 Agent 的上下文中，完成复杂的业务处理。

另一方面，用户自己查阅待办时，可以使用微信小程序，通过可视化的 UI 界面来处理待办、提醒等，用户的诉求是：易于交互和**确定性**。

### 轻量级设计

ai-todo 的轻量化主要体现在功能设计上，用户使用起来的感受是“负担小”。开发 ai-todo 的初衷，源于我个人的真实痛点与使用体验。

现在，像飞书、钉钉和企业微信等企业级协同工具都已全面支持 CLI。作为一名效率工具的重度爱好者，我在第一时间体验了飞书的 lark-cli（包含 `lark task` 和 `lark calendar` 等命令）。

【飞书 lark-cli】

然而，我很快发现，飞书的“任务（Task）”指的就是“提醒事项（Reminder）”，是从项目管理和团队协同的角度设计的，虽然功能丰富强大，但对于轻度用户来说，却因为过度设计而显得复杂鸡肋，反而起了反作用。而且，仅仅为了使用日历和提醒这两个核心功能，就必须每天登录并常驻运行一个动辄数百 MB、运行内存占用极高的庞大客户端，这实在是太重了。非企业用户没有很高的必要性去专门使用飞书。

对于大多数轻度办公的职场人来说，微信和邮件是办公的主要应用，在配合腾讯文档、金山文档等轻量工具后，此轻量化产品非常适合日常的工作场景。

“待办（Todo）”是一个更宽泛的概念。在逻辑上，它应当涵盖提醒（Reminder）、日程（Calendar）和任务（Task）。但由于“任务（Task）”模块带有重度的项目管理属性，ai-todo 坚决选择做减法，不做任务模块，不把自身打造为项目管理工具。我们仅保留最轻量的提醒（Reminder）与日程（Calendar），并引入联系人（Contacts）作为 AI 助手的上下文支撑，以保持项目的绝对轻量化：

### 开放与多平台支持

ai-todo 在开放性与多端支持上，做到了真正的平台无关与极致的轻量体验：

- **面向任意 AI Agent 开放**：通过 CLI 命令行工具，ai-todo 可以无缝开放给任意 AI Agent（如 Claude Code、OpenCode、OpenClaw 等）。它不依赖于任何特定平台本身，只要 Agent 支持调用工具（Agent Skills）即可直接接入。
- **基于微信生态的多端覆盖**：用户的图形化入口深度依赖微信生态。不仅支持手机端即开即用以及电脑端（Windows、macOS）小程序联动，更接入了微信订阅消息功能，无需客户端常驻后台，即可将提醒事项和日历日程的到期提醒直接发送到用户的微信中。
- **免安装的系统无关性**：得益于小程序的轻量化技术，ai-todo 彻底摆脱了操作系统的束缚（iOS、Android、鸿蒙均天然支持），完全没有传统 App 的下载、安装与常驻运行负担。

另外，ai-todo 专注能力层，不在小程序中内置 AI 能力，不做自然语言解析，而是专注结构化数据的处理。把任务理解的能力交给更靠近用户的 AI Agent，让 ai-todo 做可靠的执行和存储。

## 产品模块

ai-todo 主要包含 3 个核心模块：提醒、日历和通信录。以下是各模块的定义与典型使用场景：

### 1. 提醒事项（Reminder）

提醒事项是一段时间内完成即可，偏向于具有 DDL（截止日期），但时间可自由支配的事项。它回答的是：**「有什么事情需要我记得在某个截止日期前完成？」**

典型场景：

- 周五前提交报销（有截止时间，但本周内任何时间均可处理）
- 晚上记得给家人打电话（时间可自由支配，只要在今晚完成即可）
- 回家前去超市买牛奶

特点：

- 关注事情本身和完成状态，通常有截止日期（DDL）
- 时间可自由支配，不占用日历的特定时间块
- 适合轻量记录、快速捕捉

### 2. 日历（Calendar）

日历则是与时间强相关的提醒事项，类似于闹钟，但可以记录一些具体内容。它回答的是：**「我在某个特定时间需要做什么？」**

典型场景：

- 今天 14:00 开会（不需要提前准备，到点即刻参与，像闹钟一样提醒）
- 周六 10:00 和李华约定在汉中门地铁站，参观南京博物院
- 明天 19:00 和朋友在紫金大厦聚餐

特点：

- 关注明确的时间点或时间段，起到类似于闹钟的即时提醒作用
- 不需要准备，可以直接到点执行，并在日历中记录相关内容（如会议室、链接等）

### 3. 通信录（Contacts）

通信录（联系人）是 AI 个人助理的**基础上下文能力**。它最大的优势是，在任务处理时，直接编辑用户姓名或全拼，Agent 即可自动找到相关人员的信息（如邮箱、电话等）。

典型场景：

- 把今天的会议纪要发给部门的所有同事，并抄送部门领导（全部门有30名员工，包括1个领导）
- 下周有个项目，需要联系明华开会。

特点：

- 任务处理时，支持通过姓名或全拼快速检索，让 Agent 自动关联相关人员的邮箱、电话等信息
- 管理姓名、全拼、昵称、公司、邮箱、手机号等基础信息
- 深度赋能 Agent，使其稳定知道「某个人是谁，以及可以如何联系」
